## 当前实现

- 修改前 GitHub 备份分支 `backup/ocr-hd-camera-20260928`。
- 同一个 camera_link 上增加 1920×1440、5 Hz 的普通 RGB 相机，HFOV 与原传感器同为 1.047。ROS 图像/相机信息订阅仅在 POINT_8/9/10 拍照时建立，随后注销；原避障 RGB/深度保持 640×480、15 Hz。
- 不把 `/ocr_camera/image_raw` 加到 rosbag topic 列表，以免 recorder 的订阅让高清相机全程开启。只记录选中的 `/inspection/plate_capture` 和结果图。
- 利用既有停车与短帧组，保存至少两个不同源帧的高清原图和裁剪。低清 YOLO 框按 3 倍投影到同位置、同视角的高清图；两类传感器时间戳分别保存，不伪称同一检测帧。源时间差限制 0.45 s，捕获发生在停车后。
- 使用用户新包 `ros_packages/tl_vision` 的 OCR/车牌规范化代码，增加 recognition-only 接口、本地模型配置及低置信度拒识。
- 模型 `PP-OCRv5_mobile_rec` 保存于 `models/ocr/paddle/`，包含下载来源、模型文件 SHA 与许可证。主机独立 Python 3.12 虚拟环境 `/home/sz/.venvs/community-ocr`：PaddleOCR 3.7.0 / PaddlePaddle 3.3.1；完整环境锁定文件已保存。
- 字符连通区域估计文字高度，仅裁去上下背景，保留水平全宽；无足够字符候选则保留原裁剪。原图、原裁剪和真实送入识别器的输入均保存。两帧有效结果一致、置信度不低于 0.85 才确认。
- 原包规范化会把序号中的 I/O 转成 1/0；原始文字与规范化文字分别保存，验收比较规范化整牌号码，不声称原始逐字结果全部正确。
- OCR 主机进程通过共享目录异步处理，ROS 容器只发布结果。`/inspection/plate_text` 使用原包 PlateText 消息；`/inspection/plate_report` 和 `/inspection/plate_image` 保留对应源帧。人物和交通灯 YOLO 不调用 OCR。
- 场景随机材质使用 random_plate_N.jpg，独立审计按文件 SHA 对应库存真实标签，存入 audit_inputs；OCR worker 只读 job 与图像，从不读取该真值。
