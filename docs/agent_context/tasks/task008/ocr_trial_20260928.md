# Post-acceptance OCR trial — 2026-09-28

The navigation acceptance streak reached 3/3 and was pushed before OCR work.
The supplied `traffic_light_ros.zip` was inspected first: it provides YOLO
detection for people, lamps, and `license_plate`, plus a `/tl_vision/plate_crop`
image topic with a 6 px margin. It contains no OCR engine, OCR source code,
OCR dependency, or recognition weights; its README describes the crop as input
for a downstream OCR component.

## Added trial tool

[`scripts/plate_ocr_trials.py`](../../../../scripts/plate_ocr_trials.py) reads
the accepted raw image and same-frame detection JSON for POINT_8–POINT_10. It
uses the same 6 px crop margin as the supplied package and runs Tesseract with
`chi_sim+eng`, PSM 7/13, grayscale upscaling, and Otsu variants. Each result
includes raw text, normalized text, mean word confidence, and the source crop.
The official Tesseract `tessdata_fast` language models and Apache-2.0 license
are in `models/ocr/`.

The OCR path runs offline after navigation. It does not change route execution,
photo acceptance, traffic authorization, or the 3/3 navigation audit.

## Trial results

three successful runs. All nine produced a nonempty OCR candidate, but these
outputs are not reliable full plate strings. Examples of the best-by-confidence
candidate from each saved crop are:

|---|---|---|---|
| `20260928_135500` | `有` (25) | `_5NSB5TS:` (39) | `ELITES |` (39.5) |
| `20260928_135919` | `AK-OBBI7` (57) | `ER` (38) | `88K55` (33) |
| `20260928_140509` | `AK-OBBI7` (77) | `TEE |` (46.5) | `有 88K55 |` (57) |

Numbers in parentheses are Tesseract mean word confidence, not an exact-string
accuracy score. The CLI reports candidates for review and does not claim plate
identity where the text is incomplete or ambiguous.
