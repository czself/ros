# 智慧社区复赛技术方案

## 系统架构

Gazebo 发布 `/scan`、`/camera/image_raw` 和 `/my_car/odom`。GMapping 消费激光与
里程计，发布 `/map` 和 `map -> odom`；地图保存后由 map_server 重发。AMCL 在已知
地图上使用激光定位并持续维护 `map -> odom`。move_base 将全局静态地图、局部激光
障碍层和膨胀层组合，通过 DWA 输出 `/my_car/cmd_vel`。视觉节点从相机图像中用 HSV
颜色分割检测红、黄、绿灯，发布识别结果与标注图像。

## 导航与安全

机器人外形 footprint 按轮轴坐标覆盖车身、保险杠和车轮，局部代价地图膨胀半径为 0.25 m（实体
碰撞边界仍由 footprint 和障碍层决定，膨胀层只提供规划代价梯度）。最大
线速度限制为 0.12 m/s，最大角速度为 0.45 rad/s。巡检节点按顺序提交多个
`move_base` 目标；任何超时目标被取消并记录，避免卡死或持续碰撞。

## Sim2Real 策略

实车替换 Gazebo 驱动层，保持 `/scan`、`/camera/image_raw`、`/odom` 与 `/cmd_vel`
接口一致。部署前重新标定雷达与相机外参，使用 AMCL 的初始位姿估计；针对真实光照，
在 HSV 检测前加入曝光归一化，并以实际采集数据扩充目标检测训练集。局部代价地图
持续接收雷达障碍，不能只依赖静态地图。

## 演示与提交

演示依次录制：全景场景、机器人真实 GMapping 建图、保存地图、AMCL 初始定位、
多点导航及避障、相机标注结果和关键源代码。最终将本文件扩展为图文版 PDF，并随
README、源代码、地图文件和视频一起提交。
