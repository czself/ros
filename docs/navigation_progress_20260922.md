## 3. 已确认的问题

### 3.1 DWA 局部规划失败

全局 `NavfnROS` 可以生成从起点到北向车道的路径，但 `DWAPlannerROS` 多次报告：

```text
DWA planner failed to produce path
```

原因不是 RViz 没收到目标，而是局部代价地图把当前车体附近的可行控制空间判得过窄。动态障碍层还出现了疑似激光/深度自反射或传感器误标记，导致第二段直道也无法生成速度轨迹。

2026-09-22 实跑进一步确认：world 内嵌小车曾缩放而导航侧仍使用旧尺寸和旧传感器/轮轴偏移，造成 footprint、TF 与实际碰撞几何不一致。这是首段 DWA 无轨迹的直接配置原因；已按 world SDF 的实际轮轴、轮距和传感器位姿修正，仍需重新运行整段路线验证。

### 3.2 交通灯门控误判

`cmd_vel_watchdog` 曾报告：

```text
NORTHBOUND:WAIT_NO_TRAFFIC_LIGHT
```

该状态会把前进命令置零。此前它也会截断转向，导致机器人无法在停止线前调整姿态；现已改为仅禁止前进、保留原地转向。仍需在完整路线实跑中验证视觉检测在两个路口均稳定，且不依赖未稳定的检测结果。

### 3.3 白线约束已接入，尚未完成实跑验证

原先的横向偏差检查只是简化中心线模型，在第二个航点处曾因 `cross_track=0.096 m` 停车，不能作为验收证据。现在的最终速度门控以场地原始贴图为准，检测整个 footprint 覆盖的白色像素；这覆盖了车道线、边界和斑马线，不再依赖单一中心点或横向偏差。

该逻辑已通过单元测试，但还没有完成一次带 Gazebo 实际位姿、完整路线的验证。因此不得把它标记为正式白线合格。

### 3.4 路线坐标尚未冻结

`route_contract.yaml` 仍标为 `draft_from_user_diagram`。右侧车道已按真实白线地图统一为 `x=1.70`，运行时 reset 已修正为 world 中实测的出生位姿约 `(1.715, -1.600, 1.606)`，避免车体初始压在场地外边线；路线其余中心线仍需逐段通过真实白线地图验证。

在坐标冻结前，禁止将 9/9 直驱记录或任意 `move_base` 运行称作赛道合规通过。

### 3.5 地图覆盖统计口径需要修正

全图统计显示已知比例约 13.8%，但大部分未知像素属于场地外的地图画布。coverage report 已显示出生点自由、可达 frontier 为 0；后续验收应只统计场地内区域，不能把场外画布当作漏扫。

## 4. 临时验证与正式验收的区别

曾经跑通 9/9 航点的版本有以下临时条件：

- 关闭了局部动态障碍层；
- 使用直接航点控制器，而不是完整 `move_base` DWA 控制；
- 直接向 `/my_car/cmd_vel` 发布低速速度命令；
- 使用了较宽松的路线和边界处理。

因此这次结果只能证明路线和场景运动逻辑可行，不能宣称正式导航验收完成，也不能证明动态避障和白线约束已经合格。
