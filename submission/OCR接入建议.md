# 智算三行队：OCR 接入建议

建议先对比预训练的中文轻量 PaddleOCR 模型，再根据错误类型决定是否微调。当前引擎仍暂停；本文件是后续方案，不代表 OCR 已安装、运行或通过验收。

## 推荐流程

1. **准备可核验样本。** 从已保存的 POINT_8/9/10 原始 RGB 图中裁出车牌，用独立人工标注的真实号码建立小型评测表，覆盖不同号码、距离、角度与光照。同一号码的相邻帧不能冒充大量独立测试样本。
2. **先改输入质量。** 使用原始相机图，不从叠加了框/文字的标注图裁剪。留适度边缘，必要时做车牌透视矫正；选帧应看车牌局部清晰度，不能只看整图背景边缘。放大可统一输入尺寸，但不能恢复已经丢失的笔画。
3. **明确指定轻量模型。** 官方提供 `PP-OCRv5_mobile_rec` 等中文轻量模型；可先作为稳定基准。已经得到规整车牌裁剪时，考虑直接用文本识别模块；若裁剪含多行/明显杂字，再评估检测+识别。对本场景端正车牌可关闭文档方向/文档展平等附加模块，保留必要的几何校正。
4. **隔离环境和任务执行。** OCR 放在独立进程或容器，固定 PaddleOCR/PaddlePaddle 与模型版本，提前下载并保存模型 SHA；ROS 传递图片、源帧 stamp、点位和框索引。先改现有适配器以支持显式模型名称/本地模型路径，避免版本升级改变默认模型。
5. **异步识别。** 利用拍照点已有短帧组，择优送入有界队列；识别不占用 move_base/YOLO 线程。每个点位最多处理少量清晰帧，做整牌结果一致性确认。识别失败保存原图和原因，输出“未识别”，不凭文件名、材质清单或号码规则拼出答案。
6. **用准确率与耗时一起决定。** 记录整牌完全正确率、字符准确率、失败/拒识率、延迟分位数及全任务总时长。对清晰近正面的车牌仍反复错的字符，收集仿真和真实车牌样本再微调识别模型；若原图笔画已看不清，优先调取景和相机。

## 接入包的注意点

新版 `traffic_light_ros (2).zip` 确实包含 PaddleOCR 适配器、独立 OCR 节点、消息和启动文件；没有附带其模型文件。`best.pt` 属于目标检测。README 中“权重不入 Git”的说明主要针对该 YOLO 检测权重，不能据此解释 OCR 模型加载机制。

该包目前根据 PaddleOCR 2/3 API 自动选择接口，但构造器没有提供明确的识别模型名/本地模型目录；默认开启文本方向分类。接入前需补齐这些配置，按实际裁剪需要减少附加模块。必须确认 OCR 返回值解析取的是识别文字及分数，格式校验不能替代识别正确率。

中文首字、0/字母、特殊牌样式应单独统计误差。原始输出、规范化输出、置信度和有效状态分别保留；不要把格式合法当成号码正确。
